# The app now saves your plant photos inside the export before delete unlocks

**What it shows:** the JSON export only links the photos (signed URLs, 7 days). The app now downloads every photo behind those links, packs `export.json` + `photos/*` into one ZIP, hands that file to the user, and only then opens the delete button. If a photo fails, nothing is handed over, delete stays locked, and the message says how many photos failed and to try again; expired links and links to an unexpected host have their own messages. Evidence: `test-output.txt` (287 app tests, tsc clean) and `mutation-output.txt` (7 mutations in round 1, 4 more after review, each caught by failing tests). If a photo fails, nothing is saved to the device; if the server lists photos but none can be downloaded, or the photos are over the in-app size cap, the export also fails and delete stays locked. No screenshot: nothing was run on a phone or a simulator, so there is no real image to show.
