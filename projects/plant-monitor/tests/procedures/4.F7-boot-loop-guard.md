# Bench procedure: boot-loop guard and safe fallback (task 4.F7, for Peter / bench owner)

Purpose: check on a board what the host tests only prove for the decision logic (FR-D05, NFR-01, NFR-12).
NOT RUN. Needs the ESP-IDF adapter, which is not written in this slice (the guard is pure C and `main` does not call it yet). Every step below is UNVERIFIED.

Values under test are proposals, not decisions: limit 5 failed boots, fallback sleep 21600 s (6 h), 12 bytes of RTC memory.

## Steps (once the adapter exists)
1. Flash an image that resets on purpose before the cycle ends (a test-only `abort()` behind a Kconfig switch). Watch the serial log:
   boots 1 to 5 run, boot 6 prints one `NWBOOTGUARD fallback why=count ...` line and the board stops (no BLE advertising, no Wi-Fi association).
2. Fallback current (NFR-12): after the log line, 60 s mean at the battery terminal, 3.7 V, USB unplugged. Record it. Estimate to compare against: about 21.6 uA typical, 39.6 uA worst (power budget, section 12; not measured). Pass is at most 50 uA.
3. Probation: let the 6 h timer run (or shorten it in a test build). The board must run exactly one normal attempt and, with the abort still in the image, return to fallback with one more log line.
4. Confirm: flash a good image; the counter returns to 0 after one normal wake (no guard log line in 24 h).
5. Rollback: serve an OTA image that aborts on boot. The board must roll back to the previous image after 5 failed boots, not after 8, and report the previous version on the next report.
6. RTC loss: pull the cell during a boot loop, reconnect. Record whether the counter survived (expected: no, a full power loss clears RTC memory). Record what a brownout does to RTC memory on this board (UNVERIFIED either way).

## Record
Write the measured fallback current, the boot count at which fallback started, and the rollback boot count into the Agent Log. Do not change the proposed values without Arsany's decision.
