Plant Monitor app: low-fi wireframes (task 4.A1)

Leo (Full-stack) · v0.1 DRAFT for review · React Native (Expo). Grey boxes are placeholders; yellow hatched boxes are notes, not UI. Each screen carries its requirement IDs (green bar). Names of tables, fields and endpoints are from the interface contracts in PR #15 (docs/interfaces/, draft v0.1). Single self-contained file, no network.

1 · Onboarding & profile

Sign up/in, profile, delete account (FR-A01).

2 · Device setup flow (BLE → Wi-Fi → name → photo → plant details)

Five FR-A03 steps in order, with the running timer to show the 3-minute budget (NFR-03: median ≤ 180 s, none > 240 s, from app open to plant saved). Only the happy path needs taps on S10, S11 (scan), S12, S13, S14 (or skip), S15, S16. Hub pairing (S17) is optional, skipped by default and excluded from the 4.A3 acceptance until the hub requirements are accepted (T-3).

3 · Plant list, plant detail, gallery

Free users see 7 days (168 hourly means); longer ranges show a Premium chip.

4 · Alerts

Five alert types (FR-A07); each fires once (server dedupe: unique open alert per device and kind).

5 · Premium: dashboard, care tips, AI connect

Premium is a server flag (FR-P04); the app only hides what the server would refuse.

Free vs premium

Free window is 7 days, enforced by RLS on readings (ts > now() - 7 days or is_premium()), so a free user querying 90 days still gets 7. The app mirrors with lock chips; it is never the only gate.

Mismatches and gaps for Theo (T-*)

IDIssueWireframe assumption / ask
T-1FR-A03 order puts the photo (step 4) before plant details (step 5), but plant_images.plant_id is NOT NULL and the plants row does not exist yet.App keeps the photo locally and uploads after S15 saves the plant. No contract change needed, but Theo to confirm this is intended (and whether a device-level image is wanted).
Decision (Theo, 2026-11-05): confirmed; photo stays local until S15 has created the plant, then upload and insert plant_images; devices.plant_id set in the same step.
T-2Tips and analytics (FR-P01/P02) have no HTTP contract; only the tips table exists. S41/S42 cannot be typed against anything.Need endpoint specs from 4.B3/4.B4 (Sana) before 4.A6/4.A7; wireframes assume: get tips by plant_id, series 30/90 d, watering events, compare N plants.
Decision (Theo, 2026-11-05): no new REST endpoints. Tips: table tips + Edge Function POST /tips/generate. Analytics: RPCs plant_series, plant_events, compare_plants via supabase-js rpc().
T-3Hub pairing (S17, UC-13) is proposed only; hub registrar API (hub-api.md) not written. No FR-A id covers it.Keep S17 optional/skippable; need hub-api.md or drop from app scope.
Decision (Theo, 2026-11-05): S17 stays optional and last in the build order; hub scope for v1 is an open question for Arsany (recommendation: v1.1).
T-4FR-A06 expects 168 hourly points, but readings are 15-min samples (96/day, decision #1). 7 days = 672 rows.Proposal: app averages to hourly client-side (or an hourly view/RPC); confirm whose job it is and the hour boundary (UTC vs local) and whether the matrix "168 points" counts hourly averages.
Decision (Theo, 2026-11-05): server aggregates: plant_series(..., bucket_minutes := 60) returns hourly means (bucket start = UTC hour, timestamptz); larger buckets for 30/90 d.
T-5Soil calibration (FR-D10, Plan 4.F5): devices.cal_* are server-managed and there is no BLE/API contract for starting a calibration from the app.S24 shows only an entry point. Need contract (BLE endpoint or config flag) or drop from the app.
Decision (Theo, 2026-11-05): v1 has no BLE endpoint and no cloud flag; calibration is the documented button sequence (FR-D10), S24 is an instruction card; 4.F5 documents the sequence, factory default pair so the device works uncalibrated.
T-6Removing a plant: plants delete sets readings.plant_id/devices.plant_id to null and cascades plant_images; FR-A08 says "keeps/clears data as specified" but nothing is specified.S24b offers keep vs delete; Theo/Arsany to decide the rule. Photos cascade today, so "keep photos" is not possible without a schema change.
Decision (Theo, 2026-11-05): pending Arsany (A-3). Recommendation: delete photos and readings after a warning that offers export first.
T-7AI connect (S43) needs the MCP server URL and client setup text; mcp-tools.json has no URL.Sana to provide URL once 4.B5 exists; placeholder in wireframe.
T-8BLE service UUID is TBD (Mira, 4.F2) and the Expo library support for security 2 is unverified (risk O-13).No wireframe impact; 4.A3 risk.
T-9plants.area and species and city are nullable/optional in the DB; FR-A04 requires area and city (only species optional).App validates area + city as required; DB check would be stricter (not null) if Theo agrees.
Decision (Theo, 2026-11-05): agreed: plants.area and plants.city NOT NULL (PR #15, ADR-013); app validates the same.
T-10alerts.kind has 8 values; FR-A07 lists 5 groups. Also no "offline since" or per-type push settings in the contract.App maps: AI events = wetting_unexpected, waterlogged, sensor_out_of_soil, sensor_fault. No notification preferences screen (OS settings only).
Decision (Theo, 2026-11-05): accepted; mapping goes into the interfaces README. No per-type push settings; offline since = devices.last_seen_at.
T-11Device name (BLE nw-claim, devices.name) and plant name (plants.name) are two fields; FR-A03 setup order asks "name" once.App asks sensor name in S13, prefills plant name with it in S15. Confirm.
T-12readings RLS silently returns 7 days to free users, so the app cannot tell "no data" from "locked".App uses profiles.is_premium to decide whether to show lock chips; fine, just noted.
