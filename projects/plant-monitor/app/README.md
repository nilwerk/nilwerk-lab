# Plant Monitor app (tasks 4.A2 account and profile, 4.A3 device setup UI, 4.A4 slices 1 and 2 plants)

Expo (SDK 58) + TypeScript (strict). Screens: Welcome S01, Sign up / Sign in S02, Profile S03, Delete account S04, Premium sheet S40, plus (4.A4 slice 1) Plant list S20, Plant detail S21 (with hourly table S22 and metadata), Photo gallery S23, Remove plant S24b/S24c with export first, a Plants/Profile tab bar
(wireframes: `wireframes/index.html`). Requirements: FR-A01 (account), FR-P04 (plan mirrors `profiles.is_premium`), NFR-06 (own rows only, RLS), NFR-07 (delete removes all data, export first).
Brand: the aligned set approved in A-040 (`theme.ts`, `tokens.json`, `assets/` copied from `showcase/brand/app/`; regenerate there, not here). English only, strings in `strings/en.json` (A-024).

## Run
```bash
npm ci
npm run typecheck && npm test                      # typecheck + 164 unit/screen tests (no backend needed)
EXPO_PUBLIC_MOCK_AUTH=1 npx expo start --web       # whole app against an in-memory mock of Supabase (no account, no network)
```
Real backend (needs a Supabase project, Arsany's step, see `../cloud/README.md`): set these environment variables before `expo start` / EAS build. Names only, values are never committed:

| Name | What |
|---|---|
| `SUPABASE_URL` | project URL (https) |
| `SUPABASE_PUBLISHABLE_KEY` | the NEW publishable key (`sb_publishable_...`), public by design; never a secret / service-role key |
| `CONTACT_EMAIL` | address behind "Contact us" on the Premium sheet. Default `nilwerk.team@gmail.com` (A-048, the one shared mailbox for now); set another value to override, set it to an empty string to hide the link. Opens `mailto:` with subject "Plant Monitor – Premium activation" |

`app.config.ts` copies them into `extra`; `src/config.ts` reads them. Without them the app shows a "not connected to a server" message instead of crashing.

## Not done / known gaps (4.A2)
- Never run against a real Supabase project or on a phone. Web build + jsdom-free render tests only.
- `DELETE /account` is the edge function `delete-account` (deployed on project nilwerk-cloud, 4.B2b; route `/functions/v1/delete-account`, client `src/account/accountApi.ts`). Never run against the live project from the app (fakes and a fake fetch only). Base URL and publishable key come from the build env `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY`, not from code.
- No forgot-password, no data export, no plant list (the setup flow exists in 4.A3 but only against a fake). Export warning for plant removal is A-022 (separate).
- `handle_new_user()` stores only the id, so the sign-up display name is kept in auth user metadata and copied into `profiles.display_name` on the first profile load.
- **GET /export client + file hand-off (4.A9, NFR-07, FR-A01; owner decision A-106: no skip option, delete stays blocked until the user really received the export):** `src/export/exportClient.ts` (GET `/functions/v1/export?format=json|csv`, rejects empty / wrong-type / non-JSON 200s), `src/export/fileHandOff.ts` (write file and read its size back -> share sheet (native, `expo-file-system` + `expo-sharing`) or browser download (web) -> the user must confirm "I saved it"), `src/plants/realPlants.ts` (real `exportData`; resolves only after the hand-off succeeded, so `exported` cannot be set earlier). New dependencies: `expo-file-system`, `expo-sharing`. **Unverified:** not run on a phone; **the cloud has no export function** (not in `cloud/supabase/functions`, not deployed on nilwerk-cloud as of 2026-11-17), so against the real backend the export fails and delete stays blocked until a backend task builds it (route assumed `/functions/v1/export`).
- **Photos into the export archive (4.A9b, NFR-07, FR-A01, FR-A05; owner decision A-107 option b):** the JSON export only links the photos (signed Storage URLs, valid 7 days). `src/export/photoExport.ts` downloads every photo behind those URLs, `src/export/zip.ts` (own stored-ZIP writer, no new dependency) packs `export.json` (untouched bytes) + `photos/*` into ONE `plant-monitor-export-<date>.zip`, and only then does the file hand-off run. **Delete stays blocked until that whole archive is saved:** `ExportResult.complete` is true only for a JSON export whose photos were all saved and handed over; both delete screens gate on it. All-or-nothing: if any photo fails, nothing is handed over and the screen says how many photos failed (`export.photos.failed`), that the copy is incomplete and delete is locked; the same export button retries (it fetches fresh links). Expired links (date in `expires_at`, or Storage answering 400/401/403) get their own message (`export.photos.expired`). **Host check:** a photo URL is fetched only if it is https (http only for a localhost dev backend), has exactly the host of the configured Supabase URL, no credentials, and a `/storage/v1/object/sign/` path; anything else is rejected without a request (`export.photos.rejected`), redirects are refused, no Authorization header is sent. **CSV** is still handed over but never counts as complete (it lists photos, does not contain them) and does not unlock delete. **Contract:** `docs/interfaces/openapi.yaml` /export says `photos:[{plant_id, taken_at, url}]` [proposed]; PR #130 (4.B2c, not merged when this was written) adds `id`, absolute `expires_at`, `file` and `url: null` for a missing object. The client needs only `url`; the extras are optional. A photo with `url: null` has no file in Storage, so it is reported ("N photo(s) ... could not be included") and does not block delete (decision for Arsany in the PR). Tests: `photoExport`, `zip` (also checked by python `zipfile`), `realPlants` (real caller path), `deleteAccountPhotos` (screen + real service + fake fetch), plus mutation runs in `showcase/items/2026-11-18_4.A9b/mutation-output.txt`. **Unverified:** not run on a phone; not run against the real backend (export function not deployed); the whole archive is built in memory, so a very large photo library may run out of memory on a small phone (limit not measured, no size cap yet); `redirect: 'error'` is honoured by browsers but React Native's fetch may ignore it (the final URL is also checked when the platform reports it).
- Delete error wording is honest on purpose: the function releases devices and deletes photos before the auth user, so a 5xx or a dropped connection can leave data partly gone. A 401 after such an error is shown as "may already be deleted, sign in again to check", not "session expired".
- Apple/Google sign-in, store assets and the Expo dev build for BLE are later tasks.

## 4.A4 slice 2: gallery, export before delete, hourly table (mock only)
Requirements: FR-A05 (unlimited dated photos, newest or oldest first), FR-A04 (location type, room, soil type shown on detail and gallery), FR-A06 (hourly table, 168 rows), FR-D02 (24 reports a day = 24 rows with a value), FR-A06 and the readings_hourly design (a missing hour is a gap, no row), FR-A08 + A-022 + NFR-07 (export before delete; photo objects removed from storage).
- **Hourly table** (`src/ui/HourlyTable.tsx`, grid in `src/plants/hourly.ts`): columns are the readings_hourly fields of the contract (moisture_avg, temp_avg, rh_avg, lux_avg, vbat_min_mv), newest first, a missing hour is a dash. The service always returns the 168-hour grid (`hourlyGrid`). Boundary tests in `src/__tests__/hourly.test.ts` (empty, one reading, 24 readings, gap in time, window edges) and in `plantsSlice2.test.tsx`.
- **Gallery** (`src/screens/PlantGalleryScreen.tsx`): every photo of the plant is rendered (no cap, no windowed list). Mock photos have no image bytes, so tiles show the date only.
- **Export before delete** (`src/export/exportGate.ts`, `RemovePlantScreen`): the delete button stays disabled until `exportData` succeeded AND the exact name is typed. The export is account-wide because GET /export has no plant_id. The export result is metadata only (file name, counts); in a real build the file is handed over before it resolves (4.A9, see the GET /export bullet above).
- **Photo objects** (C2 gate from PR #65): after `delete_plant`, the app calls `removePhotoObjects` with the returned paths; a failure keeps the paths on the Removed screen with a retry.
- **Not in this slice:** account delete gate (DeleteAccountScreen is 4.A2), upload ("+ Add"), full-screen photo, long-press delete, real Supabase `PlantsService` (still mock only, never run against a backend).
